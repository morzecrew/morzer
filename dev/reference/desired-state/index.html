Desired state¶

An authority publishes a document for one installation, signed with its key and encrypted to that machine. The machine pulls it on a timer, verifies it, and applies it as one config apply. Nothing listens on the machine, and only names its release lets be managed can change. For setting one up, see managing from elsewhere.

The document¶

api_version: selfhost/v1alpha1
kind: desired-state
product: dotdash-relay
installation: inst_01M72B61SSWFT54B6KTJC26YD0
serial: 1794310000123
issued_at: 2026-11-10T12:00:00Z
expires_at: 2026-11-17T12:00:00Z
parameters:
  dotdash_servers: example.com,b.example.com
settings:
  installation.profile: own-site
secrets:
  vless_clients: |
    0b6c... phone pool=a
unset:
  parameters: [dotdash_address]

Below the envelope it is a change document, read by the same rules: settings, parameters, secrets and unset, each optional, names not mentioned untouched. Every envelope field is required:

Field What it is
api_version selfhost/v1alpha1
kind desired-state
product, installation which installation it is for; both must match the machine and the signature
serial a positive whole number, greater than the last one applied; a timestamp in milliseconds works
issued_at, expires_at RFC 3339 times; a document is refused at or after expires_at, which must be after issued_at

Each document is cumulative. It carries every value the authority manages for the installation, every time. A machine applies only the newest document it finds and may miss any before it, so a document holding only the latest change would drop one published before it and never fetched. A document whose values are already in force records its serial and runs no operation.

At most 1 MiB once decrypted, and the ciphertext at most 1 MiB on the target.

On the target¶

state/<product>/<installation-id>/<serial>.age
state/<product>/<installation-id>/<serial>.age.minisig
  • <serial>.age is the document encrypted with age to the machine's recipient, the age_recipient its fleet row carries.

  • <serial>.age.minisig is a minisign signature over the ciphertext, whose trusted comment names the document in the clear:

    morzer desired-state product=<product> installation=<installation-id> serial=<serial>

Each pair is written once and never replaced: the ciphertext first and the signature last. A machine takes the highest serial that has both objects, so a publish cut off before its signature leaves the previous document in force.

The machine lists state/<product>/<installation-id>, so a read-only credential with listing on that prefix is all sync.credentials needs. A credential that can list other installations' prefixes tells the machine which installations exist, even though it cannot read their documents.

A cycle¶

Each tick, or morzer sync now:

  1. List the prefix and take the newest complete pair. None: absent. No answer: unreachable.
  2. Compare its serial with the watermark: the same as the last applied or refused is current, and lower than either is replay.
  3. Verify the signature against sync.authority, then check that the trusted comment names this product, this installation and the pair's serial. Otherwise bad-signature.
  4. Decrypt with the machine's age identity, read the envelope, check it against the comment, and check expires_at.
  5. Check every name against the release's managed list. A name only the release the channel staged lists waits for that release (below). One name neither lists refuses the whole document.
  6. Apply it as one operation. The serial is written in the operation's record step, so it commits with the change and is undone with it.

Only an authenticated serial is recorded as refused. The serial in an object's name is anybody's who can write to the bucket, so a pair that fails its signature moves no watermark. A refused serial is not tried again, and a newer one is.

Names for the staged release¶

A release the channel has staged, by the update timer or update --stage, and not yet installed, may list names the installed one does not. A cycle sorts each name the document mentions:

The installed release lists it The staged release lists it What happens
yes either applied now
no yes kept for the staged release
no no, or nothing is staged the document is refused whole, unmanageable

Settings are always the installed release's. A name kept for the staged release is checked against it, and a value it would refuse refuses the document, invalid.

  • A parameter is kept pending, apart from the values in force, and nothing renders it. unset.parameters removes a pending value. A document that applies a value for the name now removes the pending one.
  • A secret is stored now, for the staged release to find, when the installed release does not declare it. One the installed release declares and does not list is refused, because storing it would change what that release runs on.

The next update to a release that declares a pending parameter takes the value as if it were given with --set, and so does the unattended tick. The update clears pending once it has recorded the values. A value its release does not declare is dropped, and the journal names it. An update that fails or rolls back keeps pending for the next one. An update to another release than the one the values were checked against checks them again, and one it refuses stops it before anything runs.

Outcomes¶

Result What happened Recorded as refused
ok the document was applied, or its values were already in force no; recorded as applied
current nothing newer than the last applied or refused document no
absent no complete pair is published no
unreachable the target did not answer, or an object could not be read no
bad-signature the newest pair is not a document the authority signed for this installation and serial, or is over the 1 MiB a document can be no
replay the newest document is older than the one applied or the one refused no
expired the newest document has expired, or the one in force has and nothing newer is published the newest, when it is the one expired
undecryptable the document is not encrypted to this machine, as after a rebuild yes
invalid the document does not parse, names another installation inside, or a value is refused yes
unmanageable it names what the release does not let be managed yes
failed its operation failed and was undone yes

A refusal records the step it stopped at, a class and the names involved, and never the error's text, which can quote the value refused. The steps are decrypt, parse, check, validate, plan, or the operation's own step. The classes are the results above, and health-check, runtime, secrets and manual-intervention for an operation that failed. The text is kept on the machine for sync status.

Commands¶

sync now¶

morzer sync now
morzer sync now --dry-run

Runs one cycle and prints its outcome. Refused while sync.enabled is off. Exits non-zero when a document's operation failed and was undone; every other outcome, a refusal included, is reported and exits 0. A failure of the machine's own before the operation runs, such as a secret store it cannot read, also exits non-zero: it refuses nothing, and the next tick tries the document again.

Flag Meaning
--unattended One scheduled tick: when another operation holds the deployment lock, exit 0, and the next tick tries again. Without it a held lock exits as a held lock does.
--dry-run Fetch, verify and plan the document, and change nothing.

sync status¶

morzer sync status
morzer sync status --json

Prints the target, the authority's key id, the interval, the last document applied and when it expires, the last refused with its step, class, names and full text, and what the last cycle found.

The authority's commands¶

state needs no installation of its own, as fleet ls needs none. It runs where the authority's key is.

state key generate¶

morzer state key generate ./authority.key

Writes a new minisign secret key, unencrypted and 0400, and prints the public key the machines pin as sync.authority. It refuses a path that exists. A key from minisign -G -W serves too; one with a password does not, since state publish runs without a prompt.

state publish¶

morzer state publish --target s3://acme-state/demo --expect ./roster.yaml \
    --product demo --installation inst_01M72B61SSWFT54B6KTJC26YD0 \
    --file ./demo.yaml --key ./authority.key

In order:

  1. Refuses an installation the roster does not list, and a roster entry with no key.
  2. Reads the document, a change document without the envelope, and checks it.
  3. Refuses a serial not newer than the newest document the authority's key signed on the target, since a pair is written once. A pair it did not sign does not count, so one planted at a high serial cannot stop it.
  4. Reads the installation's fleet row, and refuses one that does not verify against the roster's key.
  5. Stamps the envelope: the serial, the issue time, and the expiry, at least a minute later.
  6. Encrypts the whole document to the row's age_recipient, and to any --recipient. It refuses a ciphertext over 1 MiB, the most a machine reads.
  7. Signs the ciphertext with the trusted comment that names it.
  8. Writes the ciphertext, then the signature, then prunes.

The prune keeps the newest three pairs the authority's key signed and removes every other complete pair, whether an older one of its own, one an earlier key signed, or one planted there. It removes a lone object only below the serial just published, since one above it may be another publish in flight. Each pair loses its signature first. A failed prune fails nothing: the next publish prunes again.

Flag Meaning
--target The target the installation publishes its row to and pulls from. Required.
--expect The roster. Required.
--product, --installation Which installation the document is for. Required.
--file The document, or - for stdin. Required.
--key The authority's minisign secret key. Required.
--serial The serial. Default: the time in milliseconds.
--valid-for How long the document stays valid, at least 1m. Default 168h.
--recipient An age recipient to encrypt to as well, such as the authority's own. Repeat for several.
--credentials-file The target's credentials, as fleet ls takes them.
--dry-run Everything but the writes.

state ls¶

morzer state ls --target s3://acme-state/demo --expect ./roster.yaml

Every fleet row on the target, as fleet ls reads them, with the newest document published for each installation, the serial it applied, the one it refused with the step and class, and its last fetch. A row the roster does not list is shown as unexpected. Without --expect, nothing a row says is authenticated, and the signature column says so.

state facts¶

morzer state facts --target s3://acme-state/demo --expect ./roster.yaml \
    --product demo --installation inst_01M72B61SSWFT54B6KTJC26YD0 \
    --identity ./authority.age

Prints an installation's facts, as its task printed them, once three checks pass, and prints nothing otherwise:

  1. its fleet row verifies against the key the roster lists;
  2. the facts' signature verifies against that key, and its trusted comment names the installation;
  3. the facts are the ones that row names in facts_digest.

An older pair put back by a bucket writer fails the third check. Facts somebody else encrypted to the authority's recipient fail the second. Then the facts are decrypted with --identity, the authority's age identity. --json carries them in data.facts, with the row's row_published_at. A row older than a day is said to be stale on stderr: a bucket writer who puts back an older row with its own facts passes every check, and its age is how that shows.

Facts¶

A machine tells the authority what it needs to address documents to it and to others about it, such as a public key and the address it is reached at. The release names a task under published, and the machine sets sync.recipient, the authority's age recipient. Without either, nothing is published.

After every successful apply, start, update, rollback, restore and configuration change, the task runs with no arguments. It never runs after init, which starts nothing, and gives way when another operation holds the lock. Its stdout, at most 64 KiB, is encrypted to sync.recipient and signed with the machine's key, with a trusted comment naming the installation.

A row publish on a machine that holds facts writes them beside the row as fleet/<product>/<installation-id>/facts.age and its .minisig, then the row, which names their digest in facts_digest. A target that refuses the facts gets no new row. A machine with no facts yet, or whose facts were made for a recipient no longer set, publishes its row without either. Changing or clearing sync.recipient drops the facts it had; facts already on a target stay there until the next ones replace them.

A run that fails keeps the previous facts, and the row's facts_problem says why, as a class: the task's exit status, output over the bound, a run that did not start, or facts it could not encrypt, sign or keep. Never what it printed. The run is a task operation, journalled and attested like one, not sent to notify targets, and not what the row reports as the last operation.

Facts are for public halves and addresses. morzer cannot tell a secret from a fact, and a task that prints a credential sends it to the authority.

What it reports¶

Where What
Fleet row age_recipient, facts_digest, facts_problem and staged, the release the channel staged, and a sync block with the applied and refused serials, steps, classes and names, never a refusal's text, and pending, the parameters kept for the staged release, by name. A cycle publishes the row to the installation's backup targets when its outcome is news: a document applied or refused, or a result unlike the last
Statement a desired_state block naming the document's serial, ciphertext digest and the authority's key id
Notifications sync.refused once per refused document, sync.expired when a cycle first finds the document in force expired
config list, status --json the pending values, with the release they were checked against, and their names
doctor sync.authority warns when the document in force expires within a day or has expired, or the target has not answered for more than three intervals
Supervisor <product>-sync.timer and <product>-sync.service while sync.enabled is on, every sync.interval after the last tick, with up to a third of it as spread

A local change to a managed name¶

While sync is enabled, config set and config apply refuse to change a parameter, secret or setting the release lets the authority manage, and name the authority's key. --force proceeds, and the authority's next document sets the value back. update --set of a parameter the release being installed lets the authority manage, or of one pending, is refused the same way, and with --force the value given wins over the pending one. The secret commands are unchanged.

What a document can never change¶

Settings are limited to installation.domains and installation.profile, and only those the release also lists. A document can never change sync.*, which names whom the machine follows, nor release.*, update.*, policy, recipients, or backup and notify targets. Changing sync.authority is a local act, and it clears the serials the machine applied and refused, so a new authority starts a watermark of its own.

An installation imported with --mode dev drops sync.*: a sandbox keeps production's installation id and would otherwise read production's documents.
